# Phase 23: SEO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Keep route-by-locale title evidence with each metadata change.

**Goal:** Give every real non-home page a distinct, translated document title and resolve the confirmed root unmatched-URL 404 title gap without changing page content or user-facing behavior. **Approved exception:** the homepage keeps its existing shared default brand/location title — stored per-locale in the message dictionaries, but currently identical text in EN, NL, and DE: `RUNAVERA — Roermond, Limburg` — this is a deliberate scope decision, not an unresolved gap, and the homepage does not receive a bespoke, route-specific title.

**Architecture:** Keep the existing locale layout's translated default title, translated description, and `%s | RUNAVERA` title template. Add page-level metadata for each valid **non-home** route using translated SEO title messages, including the four dynamic pillar detail pages. The homepage (`app/[locale]/page.tsx`) is the approved exception above and is left without its own `generateMetadata`, so it inherits the layout's default title unchanged. For unmatched URLs, first verify the installed Next.js 16 behavior and its documented global not-found convention; its required `experimental.globalNotFound` flag is an explicit design decision because the installed documentation marks that convention experimental — and because Phase 13 already tried and rejected it on this exact installed version for a specific confirmed bug (see Task 1 Step 4 and Task 3), that history must be reconfirmed before the flag is treated as a live option at all, not assumed resolved by the passage of time.

**Tech Stack:** Next.js 16 App Router Metadata API, next-intl 4, TypeScript, existing EN/NL/DE message dictionaries.

**Spec:** `Roadmap/Roadmap.txt` Phase 23 row and Phase 23 follow-up; `CLAUDE.md` / `AGENTS.md` SEO notes and the Phase 19 root not-found finding.

## Global Constraints

- Preserve the project's existing EN/NL/DE locale routing: English is unprefixed; Dutch and German use `/nl` and `/de` prefixes.
- Keep `RUNAVERA` in the existing `%s | RUNAVERA` metadata template; translated page titles must not duplicate the brand suffix.
- Keep the layout-level localized default title and description as fallbacks; page-level metadata must not overwrite the shared translated description unless Phase 23 evidence justifies it.
- Add no SEO package, analytics service, backend, or persistent audit harness.
- Preserve all page content, navigation, visual design, and the existing localized not-found behavior.
- Do not change roadmap status or claim Phase 23 complete until metadata is verified on a production build and the final report is written.
- Do not begin Phase 24 or later work in this phase.

## Review Focus

1. **Locale coverage:** every valid **non-home** route must have a translated, route-specific title in EN, NL, and DE. The homepage is an approved exception: it keeps its existing shared default brand/location title — stored per-locale but currently identical text in EN, NL, and DE (`RUNAVERA — Roermond, Limburg`) — not a bespoke per-route title. Verify all 27 route/locale combinations, including confirming the three homepage combinations (`/`, `/nl`, `/de`) render that same identical title, unchanged, under this exception.
2. **Dynamic pillar coverage:** each of the four `/experiences/[slug]` pages must use its own translated title and reject unsupported slugs as before.
3. **Title template inheritance:** page titles should render as `<localized page title> | RUNAVERA`, exactly once, while the localized description remains present.
4. **404 boundary distinction:** exercise a URL with no matching route and a valid-locale route that calls `notFound()`; they use different boundaries and must not regress each other.
5. **Experimental routing risk:** the installed Next 16 docs mark `global-not-found` experimental, **and** Phase 13 already tried and rejected it on this exact installed version — confirmed via direct testing that it swallowed every not-found case app-wide (including genuine within-locale gaps that should show the localized page) and only respected the `experimental.globalNotFound` flag's *presence of the file*, not its actual boolean value. Do not enable that flag silently, and do not treat it as a fresh untested option; reconfirm the Phase 13 failure first (Task 1 Step 4), and surface the experimental tradeoff in review only if that reconfirmation shows the prior bug no longer reproduces.
