# RUNAVERA

Premium water-based-experiences portfolio site for VoltairStudio (Roermond/Limburg). "Design with energy. Build with intention."

## Stack

- Next.js (App Router) + TypeScript + Tailwind CSS
- ESLint + Prettier

## Structure

- `app/` — routes (nested under `app/[locale]/` since Phase 13 — see Internationalisation below), global styles, the root-level not-found boundary
- `components/` — shared UI components (e.g. `Logo`)
- `lib/` — non-UI logic (e.g. `lib/brand/logo.ts` asset registry)
- `i18n/` — next-intl routing/navigation/request config (Phase 13)
- `messages/` — `en.json`/`nl.json`/`de.json` translation dictionaries (Phase 13)
- `proxy.ts` (project root) — next-intl's locale-routing middleware, under this Next version's `proxy` naming (Phase 13)
- `public/images/` — real photography, served as-is (e.g. the Phase 5 hero photo). **Not** where logo assets live — that line existed here since Phase 1 but was never accurate; corrected in Phase 5.
- `Logo/` — original supplied brand source files, statically imported (not served from `public/`) via `lib/brand/logo.ts`. Not served directly; do not delete or rename — an external tool renamed this to `LogoandImages/` between Phase 4 and 5, which broke the build; restored in Phase 5, not repeated.

## Design tokens

Fixed art-directed palette, defined once in `app/globals.css` and exposed via the Tailwind theme. Never hardcode these hex values in components — reference the token.

| Token | Hex | Role |
|---|---|---|
| Deep Water | `#071C21` | primary dark background |
| Maas | `#294A4A` | secondary water/landscape tone |

## Typography

Display: Cormorant Garamond. Body/UI: Inter. Loaded via `next/font/google` in the root layout (weights 400/600 for Cormorant, variable for Inter — this covers the full type scale below; don't change the font-loading call without a real reason).

Type scale is implemented as plain CSS utility classes in `app/globals.css` (`@layer utilities`), not React components — keeps typography reusable without over-componentizing it. Cormorant carries Display through H3 (emotion/place/editorial moments); Inter takes over at H4 and everything structural/functional (nav, buttons, captions, metadata).

| `.text-h1` | Cormorant | 600 | 2.25rem → 3.5rem |
| `.text-h2` | Cormorant | 600 | 1.75rem → 2.5rem |
| `.text-h3` | Cormorant | 600 | 1.375rem → 1.75rem |

## Spacing

Named semantic layer on top of Tailwind v4's native `--spacing` multiplier, defined in `app/globals.css`'s `@theme` block: `--spacing-hairline` (8px, eyebrow→heading), `--spacing-tight` (16px, stacked short lines), `--spacing-content` (24px, paragraph rhythm), `--spacing-component` (40px, heading block→CTA), `--spacing-group` (64px, mobile section gap), `--spacing-section` (128px, desktop section gap), `--spacing-atmosphere` (192px, rare large desktop breathing room). Use as Tailwind utilities directly: `gap-content`, `py-section`, etc. Full-viewport/cinematic sections use `100dvh`, not these tokens — this scale governs rhythm within/between content sections only.

## Layout

`Container` (`components/Container.tsx`) is the one layout primitive, with a `size` prop:
- `full` — true edge-to-edge, zero gutter (cinematic/full-bleed sections).
- `wide` — 100% width bounded **only** by the responsive gutter (`px-6 tablet:px-12 desktop:px-20` = 24px/48px/80px), **no additional max-width ceiling**. This is deliberate: a fixed px cap (the generic "1280px centered SaaS container" pattern) is exactly what RUNAVERA's layout system exists to avoid. `wide` reuses only values already in the gutter system — no new tokens — so it stays trivial to adjust once the first real spatial/asymmetric composition is built.
- `measure` — same gutter as `wide`, plus a 65ch max-width cap for readable text. Not centered by default (no `mx-auto`) — anchor left/right per composition via `className`.

A true 12-column asymmetric grid, a `Stack` primitive, and a `Section heading` component are **explicitly deferred** — no page exists yet whose shape would justify their design; building them now would be guessing. `Container`/`Button`/`TextLink`/`Eyebrow` were built now because every future page needs them regardless of composition; those three are composition-specific and wait for real content.

Breakpoints (custom, not Tailwind's stock ones — `lg` defaults to 1024px, short of the brief's 1200px threshold): `--breakpoint-tablet: 48rem` (768px), `--breakpoint-desktop: 75rem` (1200px), used as `tablet:`/`desktop:` variants.

## UI primitives

`components/Button.tsx`, `components/TextLink.tsx`, `components/Eyebrow.tsx`, `components/Container.tsx` (flat under `components/`, matching `Logo.tsx`'s existing convention).

- **Button** — `variant: 'primary' | 'secondary'`, renders `<a>` if `href` is passed else `<button>`. Primary = solid Sunset fill, Deep Water text, sharp corners (0px radius), hover darkens ~9%. Secondary = transparent, 1px Mist border, hover shifts to Sunset. No shadow/transform/scale on hover — that's the generic SaaS card-hover trope RUNAVERA avoids. Min height 44px (touch target). Focus uses the existing global `:focus-visible` (2px Sunset outline) — no per-button override.
- **TextLink** — `variant: 'default' | 'subtle'`. Adds only interactive treatment (color, underline reveal, hover) — font size/family are inherited from context, not forced, since this is a behavior primitive, not a typography one.
- **Eyebrow** — **Mist-only**, no color prop offered at all (not even as an option) — Sunset is reserved for CTA fill/active state/focus, never a label color, and offering it as a prop would just invite the exact contradiction it's meant to prevent. Use sparingly, for real taxonomy labels (e.g. an experience pillar name) — not decorative filler above every heading; uppercase-tracked micro-labels are one of the most recognizable generic-Webflow/SaaS tells, so restraint here matters.

## Color usage

Beyond the token table above: Maas is a **background/mass** color (fills, panels, water-as-environment) — Mist is a **foreground/detail** color (text, strokes, icon lines) — never swap them. Sunset is the only "energy" color and stays episodic (CTA fill, active/selected state, focus ring, hover) — never body text, never decorative, never ambient. Calm (Deep Water/Maas/Limestone) should cover ~90%+ of any surface; that ratio is what keeps the palette reading as Energy×Calm rather than a flat dark-SaaS theme. No gradients without a specific, documented reason (e.g. literally simulating water/light falloff) — not for generic "depth."

## Motion (principles only — no library)

80% atmosphere / 20% movement. Three duration tiers, nothing more yet: Settle 150–250ms (micro-interactions), Reveal 400–700ms (content entering view), Flow 800–1600ms+ (atmospheric/cinematic, e.g. a future Current motif). Gentle ease-out only, no bounce/overshoot. Exact `cubic-bezier` curves are deferred to whenever the first real animation is built (not yet) — don't add an animation library speculatively.

## Logo rules

The supplied primary RUNAVERA emblem (`Logo/RUNAVERA.LOGO.1.png`) is the **authoritative** brand asset. Never redraw, regenerate, reinterpret, or alter its geometry/proportions. `Logo/RUNAVERA.LOGO.3D.jpg` is a presentation mockup only — not for UI use. `Logo/RUNAVERA.LOGO.ASSETS.png` is a flattened presentation/reference sheet, **not** a production asset source — never crop or extract variants from it.

Only the primary variant exists as a clean individual asset today. Secondary (monogram), tertiary (wordmark), and lockup variants are **not yet available** as production files. The logo registry (`lib/brand/logo.ts`) and `<Logo />` component (`components/Logo.tsx`) are built so those variants can be dropped in later by filling in the registry entry — no component API or layout changes required.

## No theme toggle

RUNAVERA ships one fixed, art-directed palette (see Design tokens). Do not add a light/dark/system theme toggle — this was a generic default in one of the installed agent personas that does not apply to this brand.

## Navigation (Phase 3)

`Header` (`components/Header.tsx`) mounts globally in `app/[locale]/layout.tsx` (moved from `app/layout.tsx` in Phase 13), above `{children}`. Pages that aren't a future full-viewport Arrival apply the `.pt-header` utility (reserves `--header-height`, 88px — the header's max height — permanently, so its own scroll-shrink never causes page content to jump).

- **Breakpoint**: nav collapses to the mobile trigger/takeover pattern below `--breakpoint-tablet` (768px); tablet and desktop both show the full horizontal nav. Don't move this to 1200px "for future German labels" — that was tried, reverted as speculative engineering against a feature (i18n) that isn't built (see the Phase 3 plan). If real translated strings later prove too long at tablet width, that's an i18n-phase problem to solve with real strings in hand.
- **Data**: `lib/navigation.ts` is the single source of truth for nav items — `DesktopNav` and `MobileNav` both read from it so they can't drift apart.
- **`NavLink`** wraps `TextLink` with routing-aware active state (`usePathname`, `aria-current`). Uses TextLink's `default` variant (Limestone → Sunset hover) rather than Mist — nav links are primary wayfinding UI, not muted detail text. A deliberate, documented deviation from the Phase 3 plan's literal "Mist default" line.
- **CTA hierarchy**: the nav CTA is `Button variant="secondary"` everywhere except the mobile full-screen menu's bottom CTA, which is `variant="primary"` (solid Sunset) — the one deliberate full-Sunset moment per session. A solid Sunset button in a persistent header on every page would itself violate the "Sunset stays episodic" rule above.
- **Header theme**: `theme` prop (`'dark' | 'light' | 'transparent-media'`), the *default* value supplied by whoever renders `Header` — currently `"dark"`, passed once from `app/layout.tsx`. One narrow, named exception: `pathname === "/"` forces `transparent-media` regardless of what's passed in, since the homepage's full-bleed photographic hero is the one page that actually needs it (see `Header.tsx`'s `theme` derivation). Every other route gets exactly what its renderer passed (today, that's always `"dark"`, since there's only the one render call). **This direction flipped in Phase 8**: Phase 7 originally made `transparent-media` the default with `/experiences*` as a named `dark` exception; once `/maasplassen` also needed `dark` (Phase 8), two of the site's three real routes wanted `dark` and only `/` wanted `transparent-media` — `dark` became the honest default, not a growing exception list. This is a fixed, explicit route check, not auto-detection — deliberately **not** an IntersectionObserver-based section-watching engine; no page has real in-page sections yet that would justify one. If a genuinely different case appears later, that's the point to build the real per-page mechanism this was always meant to be, not to keep flipping or appending routes to this one check. `transparent-media`'s scrim is the one documented gradient exception from the Phase 2 "no gradients without a specific rationale" rule (simulates light falloff for legibility over photography).
- **Scroll-shrink**: 88px → 64px on tablet+ only (mobile header is a constant 64px, no shrink) — subtle, 200ms, reuses the existing global `prefers-reduced-motion` foundation (no header-specific reduced-motion code needed). Logo shrinks modestly alongside it (40px → 32px). Easy to remove: it's one `isScrolled` boolean driving a couple of conditional class strings in `Header.tsx`.
- **Mobile menu**: full-screen Deep Water takeover (`MobileNav.tsx`), not a drawer/dropdown-card. Focus trap, `Escape` to close (restores focus to the trigger), scroll lock via the `.scroll-locked` utility class, starts below the (constant) 64px mobile header so the trigger — now an X — stays visible/clickable while open. Closes on link/CTA tap too (via `onClick`, not just Escape/trigger) — `Header` persists across client-side navigations since it's mounted in the root layout, so this isn't optional. Also force-closes (and releases the scroll lock) if the viewport crosses into tablet+ while open, so a resize/rotate can't orphan the lock with no visible trigger left to undo it.
- **Active link color** comes from a global `[aria-current="page"] { color: var(--color-sunset) !important; }` rule in `globals.css`, not a per-component class override — avoids depending on Tailwind's utility-ordering to reliably beat `TextLink`'s own color class.
- **Arrival hook**: `Header` accepts a `suppressed` prop (renders mounted-but-visually-inert) for Phase 4 to wire up against real Arrival logic. Not resolved now — today's `app/page.tsx` is an ordinary page, not Arrival, so it gets normal header clearance like any page.
- **Skip-to-content**: first focusable element in `app/[locale]/layout.tsx`, jumps to `#main-content`. Its label is translated server-side (Phase 13) — see Internationalisation below.
- **Language switcher**: `components/LanguageSwitcher.tsx` (Phase 13) — in the persistent header, not a separate not built item anymore. See Internationalisation below for placement/mechanism.
- **Not built yet**: `Breadcrumb` component — Experience pages exist now (Phase 7), but a single nesting level (home → one pillar page) doesn't yet justify a generalized breadcrumb primitive; a plain `TextLink` back-link does the same job today (see the Experience pages section below). Revisit if a real second nesting level appears. `/maasplassen` is real as of Phase 8; `/about` is real as of Phase 9; `/plan` is real as of Phase 10 — every real-page route the nav links to now resolves.

## Arrival (Phase 4)

`components/Arrival.tsx` — the full-viewport entry moment shown on every visit to `/`. Renders **in-flow** (not `position: fixed`), stacked directly above the homepage in `app/[locale]/page.tsx` — never a replacement for it. This is what lets a no-JS visitor simply scroll past it, or use the existing skip-to-content link, and still reach `#main-content` with zero JS required.

- **Concept**: static logo = the confluence ("where two waters meet") already depicted in the logo's own monogram (two strands merged). The animated Current = the journey that follows — extends outward from the identity, never toward it. Sequence: logo fades in → held pause → tagline fades in → Current draws outward → holds indefinitely (does **not** auto-complete) → visitor-triggered exit.
- **Repeat behavior**: Arrival appears on every homepage visit, including after the visitor has already entered. It uses no cookie or persisted visit state, so it can always be reviewed again. The rest of the homepage is already rendered beneath it.
- **User control**: one single "Enter RUNAVERA" control, present from frame one, **not auto-focused** on mount (that would steal focus from the Phase 3 skip-to-content link — it's reachable via normal Tab order instead, right after the skip link since `Header` is `inert` while suppressed). Click, Escape, or scroll all trigger the same exit. No timer ever force-completes it.
- **Header integration**: no React Context. `Header` starts suppressed, resets to suppressed when client navigation returns to the homepage, and listens for one `window` custom event (`lib/arrival-events.ts`) that Arrival dispatches on exit to become visible. `Header`'s transition list needed `opacity` added (it already toggled `opacity-0`/`100` via `suppressed` but that property wasn't in the transitioned list yet — a real one-line gap from Phase 3, fixed here).
- **The Current** (`components/Current.tsx`): two hand-authored SVG paths per breakpoint (not one rescaled) — shallow diagonal on tablet+, steep near-vertical on mobile, split at the same `--breakpoint-tablet` (768px) the nav already uses. Colors are the logo's own internal strand colors (Sunset, Mist) — no new tints. Reveals via a top-to-bottom `clip-path` wipe (`arrival-current-reveal` in globals.css), not a library. Phase 14 replaced an earlier dash reveal, which truncated under non-scaling-stroke (see Motion). The tablet+ band is `45vh`, not `60vh`. Stroke width is intentionally uniform, not tapered — true per-point taper would need a filled-ribbon path instead of a stroked line; deferred as a refinement.
- **Layout**: the identity block (logo+tagline) centers within whatever space remains above the Current band via `flex-1` — never hardcoded viewport percentages for relative positioning between the two. An earlier version used `top-[55%]` for the Current and it visibly cut through the tagline text once actually rendered — flex-based sizing was the fix, not a percentage tweak.
- **Reduced motion**: handled by the existing global rule, extended in this phase — it previously zeroed `animation-duration`/`transition-duration` but not `animation-delay`/`transition-delay`, so a delayed reveal (like the tagline's 950ms delay) would still wait out its delay before popping in. Both delay properties are now zeroed too. No Arrival-specific reduced-motion code needed as a result — a real gap in the Phase 1 foundation, not just an Arrival concern, so worth remembering for any future delayed animation.
- **Not built**: precise FLIP-style position-matching between Arrival's logo and Header's logo on exit (an approximate scale-down + Header's independent fade-in is used instead — documented simplification, not attempted pixel-matching).
- **Header route-awareness**: `Header` only suppresses itself while `usePathname() === "/"` — on any other route it's visible. On client navigation back to `/`, its state resets before paint so it stays behind the newly rendered Arrival.
- **Accessibility**: the logo and tagline inside Arrival are real brand content, not decoration — they are **not** `aria-hidden`, only the Current SVG is (via its own internal attribute). A screen-reader user reading linearly gets "RUNAVERA — Roermond, Limburg" and "Move beyond the Maas & Roer." before reaching the "Enter RUNAVERA" control, not just a bare button with zero context.
- **Scroll-exit threshold**: requires `scrollY > 15`, not any scroll event at all — guards against iOS rubber-band overscroll or sub-pixel scroll-anchoring jitter being misread as an intentional skip gesture.
- **Current min-height**: `min-h-[220px]` floor on the Current's container, on top of its `vh`-based height — the square `viewBox` stretched via `preserveAspectRatio="none"` would otherwise squash into a visibly distorted, near-flat band on a short landscape viewport (confirmed: a 926×300 viewport would compute 180px without the floor, and does render exactly 220px with it).

## Homepage (Phase 5)

`app/[locale]/page.tsx`'s `HomePage` — the real homepage, replacing the Phase 2/3 foundation placeholder entirely. It renders below Arrival on every visit, using the same in-flow stacking pattern.

- **Sections, in order**: full-bleed hero → four pillars (`id="pillars"`) → Maasplassen teaser → RUNAVERA story → closing CTA.
- **Hero**: `next/image` with `fill`, the supplied photo used exactly as provided — no color-grading, no re-encoding beyond `next/image`'s own optimization pipeline. `object-position: 50% 35%` keeps the sky/water band in frame. Bottom Deep Water scrim for legibility (the same single documented gradient exception the Header's `transparent-media` theme already uses — not a second one). Headline at `.text-display`, left-aligned — deliberately not centered, the most recognizable generic-hero convention.
- **Header theme**: at the time this phase shipped, `app/layout.tsx` passed `theme="transparent-media"` to `<Header />` as a site-wide default (Header mounts once, globally — there was still no per-page theme mechanism) — fine while the homepage was the only real page. **This flipped in Phase 8** once two more real routes needed `dark` instead — see the Navigation section above and the Phase 8 section below for the current, actual default.
- **Explore cue**: a plain `TextLink` anchor (`href="#pillars"`) in the hero — native browser anchor-scroll, no JS, respects reduced motion via the existing global `scroll-behavior: auto !important` rule.
- **Four pillars** (`components/Pillar.tsx`, new — genuinely justified by real 4× reuse, unlike earlier deferred primitives with no consumer yet): deliberately **not** an alternating zig-zag/card-grid pattern — that skeleton is itself one of the most recognizable generic travel/SaaS templates, regardless of what fills it. Instead: one consistent Deep Water background throughout (no alternating row colors — color-alternation is the most template-coded signal), each pillar at a different horizontal inset and different vertical gap (varies at both mobile and tablet+ — Private gets a deliberately larger gap at every width, not just desktop), a single thin Mist hairline threading one consistent side as a quiet "current" motif. Pure typography — no per-pillar photography exists, none invented. Section wrapped in `<section aria-labelledby="pillars-heading">` with its own Eyebrow+H2; each pillar name is an **H3** (not a peer H2) — screen-reader users need the same "these four are one group" signal sighted users get from the visual banding.
- **Maasplassen / Story**: Maas background + `wide` container (place/atmosphere) vs. Limestone background + `measure` container (the one light section on the page — brand/why, first-person-plural reflective tone, deliberately different register from Arrival's second-person tagline). Both single-instance sections, no repeated structure — what keeps them reading as teasers, not full pages.
- **Closing CTA**: `Button variant="secondary"` → `/plan`, same destination and treatment as the persistent nav CTA — fulfills the brief's own "gentle next step toward planning," not invented scope.
- **No scroll-triggered motion**: considered (a shared `useInView`/IntersectionObserver reveal), reconsidered, and dropped — the phase already introduces the site's first real photograph, first new component, and four new sections; adding the first JS-driven scroll interaction too, with no reason stronger than "it would feel nice," didn't meet the bar this project holds elsewhere. Sections render via plain document flow.
- **Attribution**: bottom-right of the hero, always visible (not hover-to-reveal — CC BY-SA can't legally be gated behind an interaction), `.text-caption`, Mist at ~65% opacity. All four required elements in one line — photographer name + source link (Davy Landman → the Commons file page), license link (CC BY-SA 2.0 → the license deed), and a "Modified" notice.
- **`Logo/` restoration**: between Phase 4 and 5, an external tool (Codex CLI) renamed `Logo/` to `LogoandImages/`, breaking the build. Fixed by restoring `Logo/` exactly as before — `lib/brand/logo.ts` needed no change, since its import was already correct once the folder existed again. The hero photo was relocated to `public/images/` instead, kept separate from brand-identity assets per explicit instruction.

## Pillar transitions (Phase 6)

`components/PillarGroup.tsx` (new) — a `"use client"` wrapper owning which pillar is currently chosen. `app/page.tsx` is an `async` Server Component and can't hold state itself, so this is where the four `<Pillar>` calls that used to sit directly in `app/page.tsx` now live; `app/page.tsx` still owns the surrounding `<section>`, its heading, and the base hairline. **No longer homepage-exclusive as of Phase 10**: `app/plan/page.tsx` renders `PillarGroup` too, wrapped in the same section/heading pattern — see the Phase 10 section below.

- **Scoped `next/link` exception**: `Pillar.tsx`'s own CTA is the only link in the site using `next/link`'s `<Link>` instead of `TextLink`'s plain `<a>` — introduced specifically so its navigation is eligible for a React `<ViewTransition>`. Its visual classes are copied from `TextLink`'s `default` variant rather than importing `TextLink` itself, since `TextLink` always renders a plain `<a>` and isn't meant to change for this one case. (Superseded in Phase 13: `TextLink`, `Button`, and `LanguageSwitcher` now also render through next-intl's `Link`, so Pillar is no longer the only `next/link`-based link. `transitionTypes={["pillar-choice"]}` is matched by the root-crossfade suppression in `globals.css`; see Motion.)
- **Chosen state**: click or Enter on a pillar's link sets `PillarGroup`'s `selectedSlug` synchronously (the click isn't `preventDefault`-ed — real navigation proceeds normally alongside it). The chosen pillar's heading and hairline tick shift to Sunset; the other three dim to ~40% opacity via `isDimmed`. This is the *entire* visible mechanism — it does not depend on `useLinkStatus()`'s `pending` ever firing (see below). Space is deliberately not wired to anything beyond its native scroll behavior — these are links, not buttons; only Enter (and click) activate them.
- **View Transition contract, closed in Phase 7**: (Superseded in Phase 14: every pillar's `<h3>` is now wrapped with `share="morph"` and `default="none"`; see Motion below.) Originally, only the chosen pillar's `<h3>` was wrapped in React's `<ViewTransition name={`pillar-name-${slug}`}>` (imported from `react`, per `node_modules/next/dist/docs/01-app/02-guides/view-transitions.md`) — the other three stay plain `<h3>` elements, so at most one `view-transition-name` exists in the tree at a time by construction, not by convention. This was the *departure* side only — Phase 7's `app/experiences/[slug]/page.tsx` now supplies the matching arrival-side element (see the Experience pages section below).
- **`useLinkStatus()` placement**: called inside a small child (`PillarLinkLabel`) rendered *inside* the `Link`, per the Next.js docs' requirement that it run in a descendant of the `Link` it reports on, not the same component that renders the `Link`. Its `pending` boolean only ever adds a small supplemental affordance (the CTA text tints Sunset) on top of the chosen-state treatment above — Next's own docs note `pending` can be skipped entirely for an already-prefetched navigation, so nothing depends on it appearing.
- **Reduced motion**: View Transition pseudo-elements (`::view-transition-old`, `::view-transition-new`, `::view-transition-group`) live outside the DOM tree the site's existing global `*` reduced-motion rule reaches — a real gap, not covered by that rule, confirmed against the Next.js docs' own reduced-motion guidance. `app/globals.css` adds a dedicated rule for them (same 0.01ms/0ms units as the existing rule, not the docs' literal `0s`, for consistency) — the same category of fix as the `animation-delay` gap found during the Arrival phase.
- **`prefetch` left at Next 16's default** (`"auto"`) — no evidence turned up during implementation or since that the `/experiences` routes need an override.
- **Not built in this phase**: no changes to `Header`, `Arrival`, `Current`, `lib/navigation.ts`, or the Maasplassen/Story/CTA sections.

## Experience pages (Phase 7)

`app/experiences/[slug]/page.tsx` (new) — the four real pillar destinations (`escapes`/`explore`/`private`/`gather`), closing the placeholder every pillar link pointed at since Phase 5. `app/experiences/page.tsx` (new) — a minimal index, added because the persistent header nav's "Experiences" link (`lib/navigation.ts`) points at bare `/experiences`, which would otherwise keep 404ing even with the four detail pages built.

- **Shared pillar data**: `lib/pillars.ts` (new) is the single source for each pillar's `name`/`slug`/`tagline`/`description` — consumed by both `PillarGroup.tsx` (homepage summary) and the new detail pages, matching `lib/navigation.ts`'s own "one source, not two" precedent. `PillarGroup.tsx` keeps its per-pillar layout `className` offsets local to itself (a homepage-composition detail, not pillar content).
- **`PillarGroup.tsx`'s `href`s**: each pillar now points at its own real `` `/experiences/${slug}` `` instead of the shared `/experiences` placeholder — no other change to Phase 6's mechanism (`transitionTypes`, `isChosen`/`isDimmed`, the `<ViewTransition>` wrap).
- **Closing the View Transition contract**: each detail page's `<h1>` (the pillar name) is wrapped in `<ViewTransition name={`pillar-name-${slug}`}>` — the exact same name Phase 6's chosen pillar carries. This is the first point a real end-to-end shared-element morph is possible and testable, not just the departure-side treatment Phase 6 could build alone.

## Internationalisation (Phase 13)

Full English/Dutch/German coverage — English stays unprefixed (`/`, `/about`), Dutch/German are `/nl/...`/`/de/...`. The URL is the sole source of truth for language; no detection, no auto-redirect.

- **Dependency**: `next-intl` (installed 4.14.8, matching the Next.js 16.3.6 / next-intl 4.14+ pairing its own docs recommend — verified against the installed package, not assumed).
- **Route restructuring**: every page moved under `app/[locale]/` (`app/page.tsx` → `app/[locale]/page.tsx`, etc.) — required even though English shows no visible prefix, since Next's App Router still resolves routing through the `[locale]` dynamic segment internally; `next-intl`'s `localePrefix: "as-needed"` (`i18n/routing.ts`) is what makes English's prefix optional in the *visible* URL without a separate unprefixed route tree.
- **`localeDetection: false`** (`i18n/routing.ts`) disables next-intl's default Accept-Language/cookie-based auto-redirect — confirmed via its own routing docs this is an all-or-nothing switch (no way to disable just one mechanism), which is fine here since both are unwanted. This is what guarantees `/about` always serves English regardless of browser language or a previously visited locale.
- **`i18n/navigation.ts`**: `createNavigation(routing)`'s `{ Link, usePathname, useRouter, getPathname }` is the single shared entry point for every locale-aware link/pathname check — not a parallel hand-rolled mechanism.
- **Locale-aware internal links (the link-prefixing fix)**: `TextLink`, `Button`'s anchor branch, and `Pillar.tsx` all render through `i18n/navigation.ts`'s `Link` instead of a bare `<a>`/`next/link`. Without this, every back-link, nav item, and CTA would silently drop a Dutch/German visitor back into the English route tree (a real gap caught in plan review, not shipped). **Disclosed side effect**: `TextLink`/`Button` were deliberately plain `<a>`, not `next/link` (Phase 3's "behavior primitive, not a routing one") — this phase changes that, since `next-intl`'s `Link` is itself `next/link`-based; they now gain client-side transitions/prefetching they didn't have before. `Pillar.tsx`'s existing scoped `next/link` exception (Phase 6, for `<ViewTransition>` eligibility) just upgrades to the same locale-aware `Link` — still the one exception, same reason. `NavLink.tsx` inherits the fix for free (wraps `TextLink`) and switches its `usePathname` source to `i18n/navigation.ts` (locale-stripped), so its Phase 11 boundary-aware active-match logic is unchanged in shape.
- **`Header.tsx`** also switches to `i18n/navigation.ts`'s locale-stripped `usePathname` — this is what lets the existing `pathname === "/"` homepage check (the `transparent-media` theme exception and Arrival suppression) keep working unchanged across `/`, `/nl`, `/de` with no new per-locale branching.
- **Language switcher** (`components/LanguageSwitcher.tsx`): in `DesktopNav` (desktop/tablet header bar) and inside `MobileNav`'s full-screen takeover (mobile) — the persistent 64px mobile bar itself stays logo+trigger only, unchanged. Uses the same `i18n/navigation.ts` `Link` with an explicit `locale` override (next-intl's documented pattern for this), so switching keeps the visitor on the equivalent page. Locale names render as endonyms (English/Nederlands/Deutsch, `lib/locales.ts`) — fixed values, not translated.
- **Translated content**: `lib/navigation.ts` and `lib/pillars.ts` now hold translation-key references / locale-invariant slugs, not literal strings — every page/component resolves copy via `getTranslations`/`useTranslations` against `messages/{locale}.json`. Pillar names/taglines/descriptions are translated; `slug`s stay locale-invariant (no real reason to localize a URL segment here), which also means the `pillar-name-${slug}` `<ViewTransition>` contract (Phase 6/7) is unaffected — it's keyed on `slug`, never on display text. Attribution rule: photographer names, Commons titles, place names, and license identifiers (`CC BY-SA 2.0`/`2.5`) stay fixed across locales as literal strings in each page (not translation keys) — only connective microcopy ("Photo:", "Modified.", "Cropped.") is a real translation key. **Dutch/German copy is my draft, not yet reviewed** — flag any phrasing issues; known rough edge already spotted: German's Explore pillar name ("Entdecken") and its "{name} entdecken" link label repeat the same word ("Entdecken entdecken") — functional, slightly redundant, worth a pass.
- **`app/[locale]/layout.tsx`** (was `app/layout.tsx`): `generateStaticParams` returns the three locales; `<html lang={locale}>` instead of hardcoded `"en"`; `generateMetadata` replaces the static `metadata` export, translating `title.default`/`description` while `title.template` (`"%s | RUNAVERA"`) stays a fixed literal (brand name, not translated). `next/font/google` calls and the `app/globals.css` import are carried over unchanged (import path updated to `../globals.css` for the new file location). `NextIntlClientProvider` wraps the **whole body shell** — skip link, `Header`, and `{children}` together, not just `{children}` — since `Header` (a Client Component, via `DesktopNav`/`MobileNav`/`LanguageSwitcher`) needs `useTranslations` too. The skip link's own text is resolved server-side with `getTranslations` — no client hook needed for one static anchor.
- **Not-found handling — the real mechanism, confirmed empirically (not as originally planned)**: `global-not-found.js` (the Next.js convention docs name for exactly this "root layout on a dynamic segment" shape) was tried first but rejected — confirmed via direct testing that once enabled, it swallows *every* not-found case app-wide, including genuine within-locale gaps that should show the localized page, not just the intended "no locale resolved at all" case. It also only respected the `experimental.globalNotFound` config flag's *presence of the file*, not the flag's actual boolean value — a real bug in this installed version, not a misunderstanding. Abandoned entirely. The working mechanism, confirmed by direct browser testing against this exact installed Next version: a nested `app/[locale]/not-found.tsx` only ever activates for an **explicit** `notFound()` call thrown from within an already-*matched* page — never for a URL that simply matches no `page.tsx` anywhere, which always bubbles to the true root `app/not-found.tsx` (required to exist at all for Next's synthetic not-found route generation to work, confirmed empirically — without it, even explicit `notFound()` calls fell through to Next's generic unstyled default). So: **`app/[locale]/[...rest]/page.tsx`** is a catch-all that does nothing but call `notFound()` — this is what turns "no page matches" into "a page matched, and it explicitly called notFound()", which correctly activates the *localized* nested `not-found.tsx`. This same catch-all is also what handles an unrecognized locale-looking segment like `/fr/about`: next-intl's `"as-needed"` prefix mode resolves it as literal English content (locale `"en"`, rest `["fr","about"]`), not as an invalid locale value — confirmed via testing, not assumed — so it lands in the catch-all with locale `"en"` and renders the English nested not-found page. `dynamicParams = false` on the layout stays as defense-in-depth (next-intl's own middleware never actually produces an invalid `locale` param in practice) rather than the primary rejection mechanism it was originally planned to be. The true root `app/not-found.tsx` (always English, no `<Header>`/nav, no locale context) is now a last-resort backstop for the rare case nothing above catches — not the main handler for unsupported locales, as first planned.
- **`proxy.ts`** (project root, not `middleware.ts`): wraps `next-intl`'s `createMiddleware(routing)` — this Next version renamed "Middleware" to "Proxy" (`node_modules/next/dist/docs/01-app/01-getting-started/16-proxy.md`), a real naming adaptation from next-intl's own `middleware.ts`-oriented examples, not a copy-paste.
- **Out of scope this phase**: `alternates.languages` via the Metadata API (next-intl's middleware already emits hreflang via the HTTP `Link` header for free — the SEO-phase item would be the redundant HTML-tag version); full SEO work generally; Phase 12/20 (mobile/responsive) work.

## Motion (Phase 14)

Audit-led pass over existing motion. Only confirmed accessibility or reliability issues were changed; durations and transitioned properties are unchanged except where noted.

- **Arrival exit focus**: at exit start, if focus is inside Arrival (or on `<body>`), focus moves to `<main id="main-content">` (`tabIndex={-1}`, `preventScroll: true`), and only then is the Arrival container set `inert`. The order matters: making a focused element inert first drops focus to `<body>`. Escape, scroll and click exits share this path. The skip link sits outside Arrival and is unaffected.
- **Mobile menu**: open and close is a 200ms opacity and visibility fade (Settle tier, ease-out). It replaces the `hidden` attribute, which made the panel snap. A closed panel is `invisible`, so it leaves the accessibility tree and focus order. On open, focus goes to the first nav link, not the container, which is not in the trap's focusable list (previously Shift+Tab from the container escaped the dialog).
- **Header scrim on `/`**: the `transparent-media` gradient is a separate `aria-hidden`, `pointer-events-none` overlay that fades with opacity when scrolled. It was previously a background-image on the header, which cannot interpolate, so it snapped while the background faded.
- **Easing**: transitions that inherited Tailwind's default easing (`cubic-bezier(0.4, 0, 0.2, 1)`) now use `ease-out`: Pillar (dimming, heading, tick, CTA), Arrival's "Enter RUNAVERA" button, the header container and logo, MenuButton, TextLink (and NavLink, which inherits it), Button, LanguageSwitcher, the skip link, the root not-found link, and the mobile panel. Arrival's container, logo and keyframes and Current's cubic-bezier are unchanged.
- **Reduced motion**: the global rule in `app/globals.css` forces transition and animation durations to 0.01ms and delays to 0ms with `!important`, so transitions and animations complete near-instantly. The `::view-transition-*` rule sets `animation-duration` and `animation-delay` the same way, also with `!important`. View Transitions are not disabled by this rule; any that run complete near-instantly.
- **Deferred, not changed**: `Button`'s `disabled:opacity-40` is not transitioned.
- **Modified clicks** (Phase 14 follow-up): Ctrl, Shift, Alt and Meta clicks on a pillar link no longer change the selection, so the origin page keeps its state; the link itself is unchanged. Verified for Ctrl and Shift in Firefox 155 and Chromium 153. Windows Meta is a browser default (same-tab navigation in Chromium, nothing in Firefox); Cmd-click on macOS was not tested.
- **Mobile menu focus on open** (Phase 14 follow-up): the open transition is `transition-opacity` only, so `visibility` flips immediately and the first nav link takes focus. Close keeps `transition-[opacity,visibility]`, so the panel fades before it is hidden.
- **Pillar selection and View Transition** (Phase 14 follow-up): every pillar heading is wrapped in `<ViewTransition name={`pillar-name-${slug}`} share="morph" default="none">`, and the detail `<h1>` uses the same name and props. `share="morph"` makes a visible chosen heading move and resize into the detail heading; `default="none"` stops each side's own crossfade, which had produced doubled glyphs. `globals.css` also sets `animation: none` on `::view-transition-new(.morph)`, `animation: none; opacity: 0` on `::view-transition-old(.morph)`, and turns off the root crossfade for navigations typed `pillar-choice`: `html:active-view-transition-type(pillar-choice)::view-transition-old(root)` and `…new(root)`. Selection is a plain urgent update, not a transition, so the dim and Sunset state appear within about 100ms even when the destination is slow. Intentional limitation: React names a heading only while it is on screen when the transition starts. When the chosen heading is visible at click, it morphs. When it is off-screen (its link may still be visible), no pair forms: navigation proceeds normally as an instant swap, with no crossfade and no duplicate, and the page does not scroll to compensate. Auto-scroll was rejected so a click never moves the page.
- **Current reveal** (Phase 14 follow-up): the desktop and mobile path groups use `visibility` rather than `display`, so crossing 48rem doesn't restart a finished reveal. The reveal is a top-to-bottom `clip-path` wipe, not a dash: under `vector-effect: non-scaling-stroke` a dash length is in screen pixels, so the fixed 300-unit dash left gaps or cut the line short (seen at 1280×800 and 390×844). Each path runs monotonically from y=0 to y=100, so the wipe completes both lines exactly. The tablet+ band is `45vh` (was `60vh`), because the 480px band pushed the line ends below a 1280×800 viewport. Verified: both paths lit to their end at 390, 768 and 1280px in all three engines, and a breakpoint crossing mid-reveal continues the animation.
- **Browser verification (final pass)**: Firefox 155, Chromium 153 and WebKit 26.6 via temporary Playwright 1.63 in the scratchpad (removed afterward). 27 suite runs against the production build (`next build`, served with `next start` on port 3100) at 1280×800 and 390×844, all passing. Checks were corrected during the work, in the test scripts rather than the product: colour-transition timing (now measures when the colour starts changing), the WebKit Tab order (see below), one locale path, one Current timing window, and the morph check was made stricter (it now requires a visible heading and a formed pair). One WebKit mobile-menu check failed on Tab order; it was changed to be Tab-informational for WebKit and rerun, and it then passed. Covered: Arrival on direct `/`, `/nl` and `/de` with a stale `runavera_arrived` cookie; Enter, Escape and scroll exits with focus on `#main-content` before `inert`, no focus-induced scroll, and no cookie written; return to `/` via site navigation and via the language switch; reduced-motion exit (47–94ms on the development server; the production check requires under 400ms); no-JS scroll and skip link; mobile menu fade, focus, Tab/Shift+Tab wrap, Escape focus restore, link/CTA/language close with scroll-lock release, and resize across 48rem; header scrim fade, height and logo shrink, ease-out on every transition, reduced motion; Current fully lit at 390, 768 and 1280px and not restarted by a breakpoint crossing; pillar selection colour starting within 150ms while the destination is delayed 1.5s, Enter activation, and Ctrl/Shift/Alt/Meta clicks leaving the origin unchanged. WebKit's default Tab order does not stop on links, so its trap and skip-link checks use programmatic focus; keyboard Tab coverage is Chromium and Firefox only. One Firefox return click timed out once at 50ms after navigation, did not recur at 350ms, and its cause is unknown. Without JavaScript, the header is server-rendered inert and hidden on `/` (measured in all three browsers); the skip link and scrolling still reach the page.
- **Pillar morph** (normal speed, destination delayed 1.5s, recorded video): with the chosen heading on screen, `::view-transition-group(pillar-name-escapes)` forms and runs 250ms in all three engines, and the root crossfade has 0ms duration. At 30fps, Chromium desktop and Firefox desktop show the chosen heading moving and resizing into the detail heading, with the header and body text single and no whole-page crossfade. Chromium mobile shows the heading briefly overlapping the tagline mid-move, not a second copy. WebKit's recording steps from chooser to detail between frames, so WebKit's visual morph is confirmed only by its animation metadata. Each run has only a few frames inside the 250ms window. Off-screen at click, no morph occurs, by design (see Pillar selection).
- **Reduced motion**: with `prefers-reduced-motion: reduce`, the pillar transition's group animation runs at 0.01ms and the root crossfade at 0ms in Chromium, Firefox and WebKit, read from `document.getAnimations()` at ready.
- **Not tested**: Cmd-click on macOS, screen-reader behaviour on real hardware, real touch devices (emulated viewports only), and a Safari with its Tab-through-links setting enabled.
